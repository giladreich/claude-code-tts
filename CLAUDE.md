# Claude Code TTS (VSCode extension) - project guide for Claude

Speaks Claude Code's output aloud: tails the session transcripts Claude Code writes under `~/.claude/projects/`, cleans the prose (never code), announces tool calls ("Bash: run tests"), and plays it through a local TTS engine. Everything is local; the only network use is explicit, user-initiated model/voice downloads.

## Layout
Directories are responsibilities: a file's home says what kind of thing it is, and the imports run mostly one way (`extension.ts` -> `ui` -> `language`/`voices`/`setup` -> `speech`/`tts`/`platform`/`session`), with two modules reached from below: `ui/prompts.ts` (asked from `setup/setupFlows.ts`, `setup/piperSetup.ts`, `voices/clone.ts`, `voices/cloneFromFile.ts`, `voices/design.ts`, `language/languageFlows.ts`) and `ui/statusBar.ts` (read by `setup/setupFlows.ts`, `voices/voiceOffers.ts`, `voices/voiceProfiles.ts`, `language/languageFlows.ts`); `core/config.ts` also reaches into `setup`, `speech` and `tts` for the paths and types it computes with. No cycles (`npx madge --circular --extensions ts src/`), and no file over 1000 lines (`test/unit/contract.test.js` fails on it; split by responsibility rather than raising it).

- `src/extension.ts` - the composition root, and the only file at the top (nothing imports it): activation, the 37 command registrations, the transcript tailer, deactivation, and the few things that exist only during activation - the settings migration, the first-run greeting, the control verbs from the watcher, reset to defaults, and the deps handed to the storage and engine flows.
- `src/core/` - what a running extension is and what it reads. `runtime.ts` (the singletons: context, output channel, speech queue, status item, tailer, translator, ownership, control, `onError`; a leaf that imports no flow), `config.ts` (where the settings the speech pipeline runs on are assembled, and nowhere else: `config()` memoised per microtask, the per-voice rate, the chunk plan per engine, `TUNING`, and `SETTING_KEYS`, which must list every setting or the contract test fails; flows still read and write single keys of their own), `settingsMigration.ts` (renames and merges, applied once at activation), `commandCatalogue.ts` (commands registered but hidden).
- `src/platform/` - what this machine has and costs. `platform.ts` (paths, executables, the interpreter the hooks run), `uvBootstrap.ts` (a private pinned `uv`, verified against its published SHA-256), `storage.ts` (disk accounting and pruning), `modelProgress.ts` (a download's size read from the cache the runtimes write).
- `src/session/` - what Claude Code is doing. `tailer.ts` (the transcripts under `~/.claude/projects/`), `sessionOwnership.ts` (which window speaks which session: oldest live window holding the folder, else the oldest window), `control.ts` (one-word commands from `~/.claude/claude-code-tts-control`), `selection.ts` (what "speak selection" resolves to).
- `src/speech/` - text to speech, above the engines. `speech.ts` (`SpeechQueue`: sequential playback, coalescing, prewarm two ahead, catch-up rate decided per chunk, preview that re-queues the interrupted utterance; `ENGINES` registry, tests inject a fake engine through the constructor), `speaking.ts` (transcript line to speech: clean, detect, translate, chunk, queue in order), `format.ts` (`cleanTextForSpeech`, `describeTool`, `chunkForSpeech` (lossless), `utterancesFromLine`), `utteranceFilter.ts` (what actually gets spoken), `voiceRates.ts` (the rate per voice), `spokenHistory.ts` (what was said, for repeating it).
- `src/tts/` - the engines and the machinery they share. `types.ts` (`Backend`/`Speaker` contracts), `synthPlay.ts` (synth-then-play: streaming sessions, prewarm vs speak, prebuffer from `typicalRtf`, native speed vs time-stretch), `pyDaemon.ts` (the stdio JSON protocol), `audio.ts` (the persistent macOS player), `system.ts`, `piper.ts`, `kokoro.ts`, `qwen3.ts`, `chatterbox.ts`, `wav.ts`, `net.ts`.
- `src/language/` - which language is spoken and who reads it. `language.ts` (detection, engine coverage, names), `translate.ts` (the Argos daemon and the recovery ladder when a model mangles the placeholders), `translationSetup.ts` (the runtime, its models, the setting), `languageSupport.ts` (what this machine can say, and fetching a voice for a language), `languageFlows.ts` (the menus behind "Languages and translation"), `glossary.ts` (terms kept in the source language).
- `src/voices/` - a voice of your own. `voiceProfiles.ts` (what a profile carries: the engine that can speak its language, the checkpoint to download, the mapping it outranks), `voiceOffers.ts` (the offers made when a voice or language changes, each remembered so it is asked once), `clone.ts` (recording one), `cloneFromFile.ts` (taking one from audio or video already on the machine: the part of the file, the stretch inside it heard in a list, the words it contains) and `design.ts` (describing one in words), `backup.ts`, `consent.ts`, `passages.ts`, `starters.ts`.
- `src/setup/` - installing what speaks. `setupFlows.ts` (the guided installs: uv, Piper, Kokoro, Chatterbox, Qwen3, consent and progress; reaches the voice list through its command, so nothing here imports a picker), `qwen3Setup.ts`, `kokoroSetup.ts`, `piperSetup.ts`, `notifySetup.ts` and `hooks.ts` (completion-sound hooks in `~/.claude/settings.json`), `diagnostics.ts` ("Check Setup"), `onboarding.ts` (which engine suits this machine and these languages), `uninstall.ts` ("Remove Everything Claude Code TTS Added": voice backup offered, hooks, models, settings) and `uninstallHook.ts` (the `vscode:uninstall` script VSCode runs after an uninstall, with no vscode module: it removes what was written under `~/.claude`, and nothing it imports may import vscode).
- `src/ui/` - anything shown or asked. `prompts.ts` (how anything is asked: `runMenu`/`menuLoop`, `pickWithBack`, `pickWithPreview`, `inputWithBack`, `pickManyWithBack`, `livePreviewPicker`; neither `window.showQuickPick` nor `window.showInputBox` is used anywhere in `src/` (a contract test walks the tree and fails on either), because they cannot carry a back button; the pickers here are built on `createQuickPick`/`createInputBox`, and nothing outside this file constructs one), `menus.ts` (the status bar menu and the four behind it, rows only), `voicePickers.ts`, `sounds.ts`, `statusBar.ts` (the one line, and the download watcher behind it), `storageUi.ts`, `voiceManager.ts`.
- `assets/` - everything not TypeScript: the Python daemons, the Swift player and recorder, the hook script, `diacritize.py`, `speech_budget.py`, preset voice samples.

## Commands
- `npm run verify` before anything is called done: format check, lint, compile, tests. `npm run format` and `npm run lint:fix` apply what can be applied; packaging runs the same gate, so nothing unformatted or unlinted ships, and `.github/workflows/ci.yml` runs it again on every push and pull request (format and lint, unit tests on Linux and Windows, the player and pipeline tests on macOS, and a packaged .vsix).
- `npm run compile` (cleans `out/` first); `npm test` (unit + integration + activation smoke, sequential, ~85 s); `npm run test:unit`. The tests load `out/`, never `src/`, so a source change is compiled before it is tested, or the previous build is what passes.
- `npm run package` (never bare `vsce package`) writes `README.marketplace.md`, the store page without the blocks marked `github-only`, and packages with `--readme-path`; the suite runs first through `vscode:prepublish`. Then `code --install-extension claude-code-tts-<v>.vsix`, and reload every VSCode window (each keeps the version it started with).
- Diagnostics live in the extension's globalStorage: `player.log`, `kokoro-daemon.log`, `qwen3-daemon.log`, `qwen3-design.log`, `chatterbox-daemon.log`, `translate-daemon.log`; the "Claude Code TTS" output channel lists what was spoken.

## Rules that came from real bugs (keep them)
- No language is named in anything a user reads, in a setting description, or repeatedly in one source file: `test/unit/neutral.test.js` enforces it, and the catalogue files are the listed exceptions.
- Settings are grouped sections with `order` and `tags: ["advanced"]`; anything naming a program to run is `scope: machine` and listed under `capabilities.untrustedWorkspaces`.
- A command hidden from the palette must still be reachable from a flow, or listed in `src/core/commandCatalogue.ts`.
- Removing or renaming a setting means an entry in `src/core/settingsMigration.ts` and a test; users must not silently lose a value. The whole section moved once, from `claudeVoice.*` to `claudeCodeTts.*`, when the Marketplace refused the name: `PREVIOUS_SECTION` carries every key across at activation, and `SETTING_KEYS` is what tells it which keys to look for.
- The config object is mutated in place and engines hold a reference to it, so per-request settings (style, pause scale, idle unload, rate) reach the next sentence without a model reload. Never replace `this.config`.
- Tests must be silent (volume 0) and offline; daemons are tested against fake model modules on `PYTHONPATH`; the pipeline test uses its own `TMPDIR` because the live extension writes stream parts to the shared temp dir.
- Never call `node.stop()`/`pause()` while holding the player lock (deadlock); every player reply carries the stream id (stop-then-play race).
- Never retune tempo mid-sentence for catch-up; Piper is the one engine that synthesizes at the requested speed (`nativeSpeed`); Kokoro's own speed control measured 10-25% off, so its rate is carried by the player's pitch-preserving time-stretch, as are Qwen3's and Chatterbox's, prebuffered from the measured realtime factor (`observedRtf`). Do not add parallel Qwen3 daemons for throughput: measured, one generation saturates the GPU (1, 2 and 3 daemons all totalled ~0.57x realtime), and quantized checkpoints were no faster.
- A voice or engine change restarts the sentence in progress (`restartCurrent`) so the switch is heard at once; rate/volume changes must not.
- The player's time-pitch unit is a phase vocoder, so it is kept out of the path when it has nothing to do: `playbackTempo` snaps a tempo within 3% of 1 to exactly 1 and `wavplayer.swift` bypasses the unit at 1 (measured: at 1.02x it overshot a full-scale utterance to 1.36 and the output clipped 0.19s in). The neural daemons leave headroom for what it does stretch (`soft_limit`: untouched below 0.7, a tanh knee up to 0.89; a tanh over the whole signal measured 3.6% harmonic distortion at 0.6 and was heard as grit), because the codec decoder saturates at 0 dBFS. Catch-up starts only for a real backlog (3 sentences or 600 chars) and moves 4% per sentence (`RATE_STEP`): a rate that followed the queue length lurched between 1.0x and 1.2x sentence to sentence, and every stretched sentence is a vocoder sentence.
- Qwen3 presets babble occasionally: keep the runaway cutoff (`expected_seconds`) and the style instruction; clone references are 6-12s with a transcript that matches the audio exactly. Clones are generated through `_generate_icl` directly with the daemon's repetition penalty (1.1): `generate()` raises it to 1.5, which measured flatter than the speaker (pitch variety 0.19 against the recording's 0.31, spectral flatness 0.72 against 0.64; 1.1 gave 0.23 and 0.52) at the same runaway rate (1 in 20). The daemon falls back to `generate()` when that private path no longer takes its arguments.
- Do not add pronunciation hacks for specific words (substitutions are the user's setting). Keep the UI interactive without awkwardness: previews on highlight, instant skip/mute, nothing lost to an audition.
- A file out of scope still has its position moved to the end, so widening the scope does not replay a past session; the stat that does it is async, so the scope is checked again in its callback. Without that, a scope widened in the same instant as a write stepped over the line and nothing ever spoke it (`test/unit/tailer.test.js` forces the interleaving through the scope predicate rather than waiting for it).
- Activation must not block: no synchronous Python/Piper probes (check venvs on disk). `hasCommand` reads the PATH directories with `fs` rather than running `which`, because choosing the Linux engine asks three times at activation and once per engine rebuild; `test/unit/commands.test.js` fails on a spawn there, and only on Linux, which is what CI is for.
- Every Python child is started with `pythonEnv()`: Windows decodes a pipe with the system code page, so a request carrying Chinese reached the daemon as mojibake, the speech budget counted two words instead of sixteen characters, and the sentence was cut to half a second. A test in `test/unit/platform.test.js` fails on a `spawn(python` without it.
- Anything that takes a platform as an argument must not read the machine it runs on: `resolveNodeCommand` split a macOS PATH on the host's delimiter and found no node at all on Windows, and quoting a Windows path with backslash escapes puts the escapes into the path.
- A known Claude Code limitation: mid-turn prose is often not written to the transcript; do not "fix" it in the extension, it is documented in the README.

## Docs
- `docs/ARCHITECTURE.md` (diagrams, protocols, dependencies), `docs/REFERENCE.md` (every setting with its default, every command with its title, sizes and speeds), `docs/GUIDE.md` (how a person sets it up), `docs/PRIVACY.md` (what never leaves the machine, every network call), `README.md` (the store page: features and the shortcut table, under 12,000 bytes), `docs/SKILLS.md` (procedures). `test/unit/docs.test.js` fails if a setting is missing from the `docs/REFERENCE.md` table or documented with a default that no longer matches `package.json`, if a command has no row there with its current title, if a keybinding is missing from the README table for either platform, or if a link between the docs does not resolve, so update `docs/REFERENCE.md` in the same change.

## Style
- Prettier decides layout (120 columns, `.prettierrc.json`); do not hand-format around it. Where line breaks carry meaning (words grouped by theme, speakers grouped by accent, flag/value pairs in an argument list) mark the literal `// prettier-ignore` and say why in the comment above it.
- ESLint decides what may be written (`eslint.config.mjs`): braces on every branch, a blank line between declarations, no floating promise, nothing unused. A rule that fires on an idiom this codebase means (`catch {}`) is configured, not disabled per line.
- ASCII punctuation only in code, docs and messages (no em dashes, no arrows); emoji never in code/commits/docs.
- Comments explain why, briefly. Changelog entries are user-facing and factual. Version bumps go with a changelog entry.
- Commit messages: one imperative line; no promotional text.
